# Smart Proxy UI

Локальный прокси на mitmproxy с веб-интерфейсом для создания правил подмены HTTP(S) запросов и ответов. Предназначен для QA в разрешённом тестовом окружении.

## macOS — установка

Требуется Python 3.12 (через Homebrew: `brew install python@3.12`).

```bash
cd smart_proxy_ui
$(brew --prefix python@3.12)/bin/python3.12 -m venv venv
source venv/bin/activate
python -m pip install -U pip
python -m pip install -r requirements.txt
```

## Запуск

```bash
mitmdump --listen-host 0.0.0.0 --listen-port 8080 -s proxy.py
```

В браузере Mac открыть **http://127.0.0.1:8765**. Правила сохраняются в `rules.json` и действуют сразу после «Сохранить».

### Телефон

1. Телефон и Mac должны быть в одной Wi-Fi сети.
2. Узнать локальный IP Mac: `ipconfig getifaddr en0` (или `networksetup -getinfo Wi-Fi`).
3. В настройках Wi-Fi телефона выставить HTTP-прокси: **IP Mac** и **порт 8080**.
4. На телефоне открыть `http://mitm.it`, установить сертификат для HTTPS. На iOS включить доверие к сертификату в «Настройки → Основные → Об этом устройстве → Доверие сертификатам».
5. Некоторые приложения с certificate pinning могут не пропускать перехват; не обходите ограничения без разрешения.

**Безопасность:** веб-панель по умолчанию доступна только на Mac (`127.0.0.1:8765`). Сам прокси слушает интерфейсы для работы телефона. Используйте только для своего трафика и разрешённого тестирования. Не перенаправляйте на него чужой трафик. Закройте прокси после тестов.

## Правила

- **URL:** `exact` — точное совпадение целого URL; `contains` — подстрока; `glob` — маска (`*`); `regex` — регулярное выражение.
- **Метод:** любой, GET, POST и т. д.
- **Фазы:** запрос и ответ можно включать отдельно в одном правиле.
- **Body:** `none` — оставить исходное; `replace` — полностью заменить только тело; `json_merge` — рекурсивно обновить указанные ключи JSON-объекта (остальное останется прежним).
- **Headers:** можно добавлять/переписывать отдельные заголовки и удалять выбранные. Прочие заголовки не меняются. Для body mitmproxy автоматически обновляет Content-Length.
- **Content-Type:** по умолчанию не меняется. Если вводишь JSON и сервер вернул другой тип, укажи `application/json`.
- **HTTP status:** меняется только если указан в настройках ответа.
- **Порядок:** все подходящие активные правила применяются сверху вниз.

Пример динамического id в URL:
- `contains` + `/api/v1/limits` — правило работает при любых query-параметрах (например `?idn_code=...`).
- `glob` + `https://test.example.kz/api/v1/users/*/limits` — меняется любой segment id.
- `regex` + `/users/[^/]+/limits(?:\\?|$)` — id любой, но другие сегменты должны совпадать.

## Важно

Это именно **изменение трафика** (не отключает реальный запрос и не формирует искусственный ответ вместо backend). Режим ответа работает после получения серверного ответа. Для полностью офлайн-моков можно добавить отдельный режим short-circuit в будущих версиях.
