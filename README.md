# Smart Proxy UI

Локальный прокси на базе **mitmproxy** с веб-интерфейсом для создания правил подмены HTTP(S) запросов и ответов.

Поддерживаемые операционные системы:
- macOS (Intel и Apple Silicon)
- Windows 10 / Windows 11

Предназначен для QA и тестирования приложений в разрешённом тестовом окружении.

## 1. Требования

Перед установкой необходимо иметь:

- Python 3.12
- Доступ к терминалу (Terminal на macOS или PowerShell / CMD на Windows)
- Интернет для установки зависимостей
- Телефон и компьютер в одной локальной сети Wi-Fi, если планируется тестирование мобильных приложений

## 2. Установка на macOS

### Шаг 1. Установить Python 3.12

Через Homebrew:

```bash
brew install python@3.12
```

Проверить версию:

```bash
$(brew --prefix python@3.12)/bin/python3.12 --version
```

### Шаг 2. Создать виртуальное окружение

Перейти в папку проекта:

```bash
cd smart_proxy_ui
```

Создать окружение:

```bash
$(brew --prefix python@3.12)/bin/python3.12 -m venv venv
```

Активировать:

```bash
source venv/bin/activate
```

### Шаг 3. Установить зависимости

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## 3. Установка на Windows 10/11

### Шаг 1. Установить Python 3.12

Скачать Python 3.12 с официального сайта:

https://www.python.org/downloads/

Также можно установить через PowerShell:

```powershell
winget install --id Python.Python.3.12 -e
```

После установки открыть новый терминал и проверить:

```powershell
py -3.12 --version
```

### Шаг 2. Создать виртуальное окружение

Открыть PowerShell в папке проекта или перейти в неё:

```powershell
cd smart_proxy_ui
```

Создать виртуальное окружение:

```powershell
py -3.12 -m venv venv
```

Активировать:

```powershell
.\venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скриптов, выполнить:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

После этого повторить активацию. Изменение политики действует только в текущем сеансе PowerShell.

**Альтернатива через CMD:**

```bat
venv\Scripts\activate.bat
```

### Шаг 3. Установить зависимости

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## 4. Запуск прокси

Команда одинаковая на macOS и Windows при активированном виртуальном окружении:

```bash
mitmdump --listen-host 0.0.0.0 --listen-port 8080 -s proxy.py
```

После запуска:

- HTTP(S)-прокси работает на порту `8080`.
- Веб-панель работает на порту `8765`.
- Правила хранятся в файле `rules.json`.
- Изменения правил применяются после нажатия «Сохранить».
- Терминал с запущенным прокси должен оставаться открытым.

Открыть веб-интерфейс на компьютере:

**http://127.0.0.1:8765**

Для остановки прокси нажать `Ctrl + C` в терминале.

## 5. Подключение телефона

Поддерживаются iOS и Android.

Телефон и компьютер должны находиться в одной локальной сети.

### Шаг 1. Узнать IP-адрес компьютера

**macOS:**

```bash
ipconfig getifaddr en0
```

Если команда не показывает адрес:

```bash
networksetup -getinfo Wi-Fi
```

**Windows:**

Открыть PowerShell или CMD:

```powershell
ipconfig
```

Найти активный сетевой адаптер Wi-Fi или Ethernet и посмотреть значение `IPv4 Address` / `IPv4-адрес`.

Например:

```text
IPv4 Address: 192.168.1.105
```

Здесь `192.168.1.105` — пример IP-адреса компьютера.

### Шаг 2. Настроить прокси на телефоне

**iPhone:**

1. Открыть «Настройки → Wi-Fi».
2. Нажать значок информации возле подключённой сети.
3. Перейти в раздел «Настройка прокси».
4. Выбрать «Вручную».
5. В поле «Сервер» указать IP компьютера.
6. В поле «Порт» указать `8080`.
7. Сохранить настройки.

**Android:**

1. Открыть настройки Wi-Fi.
2. Выбрать подключённую сеть.
3. Открыть дополнительные параметры или изменить сеть.
4. Найти настройки прокси.
5. Выбрать «Вручную».
6. Указать IP компьютера и порт `8080`.
7. Сохранить настройки.

Названия пунктов могут различаться в зависимости от модели телефона и версии Android.

### Шаг 3. Установить HTTPS-сертификат

На телефоне с настроенным прокси открыть:

**http://mitm.it**

Выбрать операционную систему телефона и установить сертификат mitmproxy.

**Дополнительно для iOS:**

После загрузки профиля:

1. Открыть «Настройки → Основные → VPN и управление устройством».
2. Установить загруженный профиль.
3. Перейти в «Настройки → Основные → Об этом устройстве».
4. Открыть «Доверие сертификатам».
5. Включить полное доверие к сертификату mitmproxy.

**Для Android:**

Установить сертификат через настройки безопасности устройства. Некоторые приложения Android не доверяют пользовательским CA-сертификатам, поэтому для их тестирования может потребоваться соответствующая конфигурация тестовой сборки приложения.

Некоторые приложения используют certificate pinning и могут отклонять перехваченные соединения. Не обходите эти ограничения без разрешения.

## 6. Брандмауэр Windows

Windows Defender Firewall может блокировать подключение телефона к прокси.

Если при запуске появляется запрос на разрешение доступа к сети, разрешить доступ для **частных сетей**.

Если телефон не может подключиться:

1. Проверить, что прокси запущен.
2. Проверить IP компьютера и порт `8080`.
3. Убедиться, что телефон и компьютер находятся в одной сети.
4. Проверить правила брандмауэра Windows.
5. При необходимости разрешить входящие TCP-подключения на порт `8080` только из доверенной локальной сети.

Не рекомендуется открывать порт в публичных сетях или перенаправлять его из интернета.

Веб-панель по умолчанию доступна только локально:

```text
http://127.0.0.1:8765
```

## 7. Правила подмены

### URL

Доступны четыре типа сопоставления:

- `exact` — полное совпадение URL.
- `contains` — URL содержит заданную подстроку.
- `glob` — сопоставление по маске с `*`.
- `regex` — регулярное выражение.

### HTTP-метод

Можно выбрать любой метод или конкретный:

- GET
- POST
- PUT
- PATCH
- DELETE
- Другие HTTP-методы

### Фазы обработки

В одном правиле можно независимо активировать:

- Подмену запроса (Request).
- Подмену ответа (Response).

### Body

Режимы изменения тела:

- `none` — оставить оригинальное тело.
- `replace` — полностью заменить тело, не изменяя остальные части сообщения без дополнительных настроек.
- `json_merge` — рекурсивно обновить указанные ключи JSON-объекта, сохранив остальные поля.

### Headers

Можно:

- Добавлять новые заголовки.
- Изменять существующие заголовки.
- Удалять выбранные заголовки.
- Оставлять остальные заголовки без изменений.

При изменении тела mitmproxy автоматически актуализирует `Content-Length`.

### Content-Type

По умолчанию не изменяется.

Если сервер возвращает другой тип данных, а подмена использует JSON, можно указать:

```text
application/json
```

### HTTP Status

Код HTTP-ответа изменяется только в том случае, если он явно указан в настройках правила ответа.

### Порядок применения

Все подходящие активные правила применяются последовательно, сверху вниз.

## 8. Примеры правил

**Пример 1. Подмена запроса с динамическими query-параметрами**

Тип сопоставления:

```text
contains
```

URL:

```text
/api/v1/limits
```

Подходит для:

```text
https://test.example.kz/api/v1/limits
https://test.example.kz/api/v1/limits?idn_code=123
https://test.example.kz/api/v1/limits?idn_code=456
```

**Пример 2. Динамический ID в URL**

Тип сопоставления:

```text
glob
```

Маска:

```text
https://test.example.kz/api/v1/users/*/limits
```

**Пример 3. Регулярное выражение**

Тип сопоставления:

```text
regex
```

Выражение:

```regex
/users/[^/]+/limits(?:\?|$)
```

Позволяет сопоставлять запросы с разными ID пользователей без ручного создания нового правила для каждого ID.

## 9. Особенности работы

Smart Proxy UI изменяет реальный HTTP(S)-трафик.

**Подмена запроса:**

1. Приложение отправляет запрос.
2. Прокси перехватывает запрос.
3. Применяются подходящие правила Request.
4. Изменённый запрос отправляется на backend.

**Подмена ответа:**

1. Backend обрабатывает запрос.
2. Backend возвращает ответ.
3. Прокси применяет подходящие правила Response.
4. Приложение получает изменённый ответ.

Важно: прокси не отключает реальный backend-запрос и не создаёт искусственный ответ вместо backend.

Для полностью офлайн-моков в будущих версиях можно добавить отдельный режим `short-circuit`.

## 10. Безопасность

- Используйте прокси исключительно для своего трафика и разрешённого QA-тестирования.
- Веб-интерфейс по умолчанию доступен только с компьютера.
- Прокси на `0.0.0.0:8080` принимает подключения с доступных сетевых интерфейсов — используйте его только в доверенной сети.
- Не перенаправляйте на прокси чужой трафик.
- После завершения тестирования останавливайте прокси.
- На телефоне отключайте ручную настройку прокси после тестов.
- Удаляйте тестовый CA-сертификат с устройств, когда он больше не нужен.
- Не передавайте файлы сертификатов и приватные ключи mitmproxy посторонним.
